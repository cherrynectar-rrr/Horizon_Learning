# Block 01 — Foundation

> 从“会写程序”走向“开始用算法思维分析程序”。

[← 返回 Algorithm Course 首页](../README.md)

## 1. 这个 Block 在做什么？

Block 01 不追求一开始就学习高难度算法。

这一阶段先建立以后会反复使用的基础能力：

- 看懂一个程序真正做了多少工作；
- 区分时间成本和空间成本；
- 熟悉数组、字符串这些最基础的数据载体；
- 观察排序以后出现的新结构；
- 开始利用“有序性”“单调移动”“重复计算”等规律优化朴素方法；
- 不只会写出答案，还会解释为什么这样做、复杂度是多少、边界在哪里。

Block 01 的核心不是记住几个模板，而是第一次形成这样的习惯：

> **先理解问题和朴素方法，再寻找可以利用的结构。**

## 2. 为什么按这个顺序？

课程顺序不是随机的。

```text
Time / Space Complexity
        ↓
Arrays / Strings
        ↓
Sorting
        ↓
Binary Search
        ↓
Two Pointers
        ↓
Prefix Sums
        ↓
Basic Algorithmic Thinking
```

### Complexity

先学会问：数据规模变大以后，这段程序还能不能跑得动？需要多少额外空间？

没有复杂度意识，就很难理解后面的“优化”究竟优化了什么。

### Arrays & Strings

然后熟悉最基础的数据组织方式，并观察不同操作为什么具有不同成本。

### Sorting

排序第一次让我们主动改变数据的组织方式。数据变得有序以后，很多原本做不到的优化开始出现。

### Binary Search

二分查找第一次明显利用 **有序性**：一次比较就能排除一半搜索空间。

### Two Pointers

当前课程中的双指针例子继续利用升序结构，通过两端指针的单调移动排除不可能的情况。

### Prefix Sums

下一步将开始利用另一种结构：**如果某些计算以后会反复使用，能不能提前算好并保存？**

这会引出最基础的预处理思想。

## 4. 每一节课怎么学？

页面表面保持简单，但默认学习流程是：

```text
先尝试
→ 朴素方法
→ 暴露问题
→ 引导发现
→ 小数据手推
→ 自己实现
→ 运行与调试
→ 分析复杂度
→ 闭卷提取
→ 以后间隔复习与交错练习
```

第一次学习时，不急着背模板。

复习时，也不默认从头重读 README，而是先尝试回忆、手推和重新实现，再回来检查遗漏。

## 5. Block 01 的毕业目标

完成 Block 01 后，希望能够面对一个基础问题，自然开始问：

1. 最直接的方法是什么？
2. 它为什么正确？
3. 数据规模变大以后需要多少时间和空间？
4. 数据本身有没有可以利用的结构？
5. 是否存在重复工作？
6. 能不能通过排序、缩小搜索范围、单调移动或预处理减少工作？
7. 我的代码在边界情况下还成立吗？
8. 我能不能不看答案，把思路和复杂度解释给别人？

如果这些问题开始变成习惯，Block 01 就完成了它真正的使命。
