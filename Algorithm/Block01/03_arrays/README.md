## 1. 本课概览

这一课开始真正观察一种最基础的数据结构：数组。

重点不是背“数组定义”，而是理解：

> **同一个数组，不同操作为什么会有不同成本？**

本课真实练习覆盖过：

- 已知下标读取元素；
- 按值线性查找；
- 理解中间插入 / 删除为什么需要移动元素；
- 原地反转数组。

完成本课后，应能够解释这些操作对应的时间 / 空间成本，并读懂当前 `main.cpp` 中的原地反转实现。

---

## 2. 直觉 / Intuition

假设数组是：

```text
index: 0  1  2  3  4
nums:  5  8  2  9  1
```

如果已经知道要访问 `nums[3]`，我们可以直接定位到它。

但如果只知道“我要找值 9”，并不知道它在哪个下标，就只能从前往后检查，直到找到它或者确认不存在。

这两个问题看起来都叫“找一个元素”，但因为已知信息不同，成本完全不同。

这节课第一次让我们明显感受到：

> **数据结构本身的组织方式，会决定某些操作快、某些操作慢。**

---

## 3. 核心思想 / Core Idea

### 已知下标访问 / 修改

```cpp
nums[i]
```

只需要定位一次，因此通常看作 `O(1)`。

### 按值线性查找

不知道目标在哪，只能逐个比较。最坏情况下需要把整个数组看完：`O(n)`。

### 中间插入 / 删除

数组中的元素按顺序连续组织。如果中间位置插入一个新元素，后面的元素通常需要整体向后移动；删除也类似，需要把后面的元素向前补。因此中间插入 / 删除通常具有 `O(n)` 的移动成本。

### 原地反转

反转数组不一定需要创建一个新数组。我们可以直接交换：

```text
第 0 个 ↔ 最后一个
第 1 个 ↔ 倒数第二个
...
```

只需要处理大约一半位置，但数量级仍随 `n` 增长，所以时间是 `O(n)`；因为直接修改原数组，辅助空间是 `O(1)`。

---

## 4. 手推 / Hand Simulation

以：

```text
nums = [1, 2, 3, 4, 5]
```

为例。

第一次交换：

```text
[5, 2, 3, 4, 1]
```

第二次交换：

```text
[5, 4, 3, 2, 1]
```

中间的 `3` 不需要和自己交换。

因此循环只需要执行 `nums.size() / 2` 次左右。这里虽然只做 `n/2` 次交换，但大 O 会忽略常数倍，所以仍然是 `O(n)`。

## 5. 实现 / Implementation

本课真实代码：[`main.cpp`](./main.cpp)。

当前真正运行的是原地反转：

```cpp
void reverseArray(std::vector<int>& nums)
{
    for (std::size_t i = 0; i < nums.size() / 2; i++)
    {
        std::swap(nums[i], nums[nums.size() - 1 - i]);
    }
}
```

这里有两个关键下标：

```text
i
nums.size() - 1 - i
```

当 `i` 从左往右移动时，另一个位置会从右往左移动。

当前文件中还保留了早期练习痕迹：

- `getElement`：已知下标读取；
- `contains`：线性查找。

它们没有被删除，因为这些正是这一课真实走过的学习路径。

## 6. 复杂度 / Complexity

| 操作 | 时间复杂度 | 辅助空间 | 原因 |
| --- | --- | --- | --- |
| 已知下标读取 / 修改 | `O(1)` | `O(1)` | 直接按下标访问 |
| 按值线性查找 | `O(n)` | `O(1)` | 最坏需要遍历整个数组 |
| 中间插入 / 删除 | `O(n)` | 取决于容器实现 | 后续元素可能需要移动 |
| 原地反转 | `O(n)` | `O(1)` | 大约交换 `n/2` 次，直接修改原数组 |

---

## 7. 常见错误 / Common Mistakes

### 以为“只交换 n/2 次”就是 `O(n/2)`

复杂度通常忽略常数因子，所以写作 `O(n)`。

### 反转时右侧下标少减一个 `1`

数组最后一个合法下标是 `size - 1`，不是 `size`。

### 把查找和已知下标访问混为一谈

`nums[i]` 快，是因为下标已经知道；“找到值等于 target 的位置”是另一个问题。

### 为了反转再创建一个同样大小的新数组

可以做到，但那会把辅助空间从 `O(1)` 变成 `O(n)`。当前练习特意采用原地反转。

## 9. 快速复习 / Quick Review

1. 为什么已知下标访问通常是 `O(1)`？
2. 为什么按值查找最坏是 `O(n)`？
3. 为什么数组中间插入 / 删除可能很贵？
4. 原地反转为什么是 `O(n)` 时间、`O(1)` 辅助空间？
5. `nums.size() - 1 - i` 表示哪个位置？

### 一句话唤醒

> **数组让“按位置访问”很快，但查找、移动和整体变换仍可能随着 `n` 增长。**
