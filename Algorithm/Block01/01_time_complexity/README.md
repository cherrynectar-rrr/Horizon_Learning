# Time Complexity — 时间复杂度

[← 返回 Block 01](../README.md)

## 1. 本课概览

这一课解决一个最基础的问题：

> 两段代码都能得到正确答案，为什么其中一段可能在数据变大以后慢得多？

时间复杂度不关心某台电脑上精确运行了多少毫秒，而是关心：

> **当数据规模 `n` 增长时，算法需要做的工作量如何增长。**

本课的真实练习是：读入 `n` 个整数，然后线性扫描找到最大值。

完成本课后，应能够：

- 理解 `O(1)`、`O(log n)`、`O(n)`、`O(n log n)`、`O(n^2)` 的增长直觉；
- 从循环结构判断最基础的时间复杂度；
- 解释当前 `main.cpp` 为什么是线性时间；
- 不把复杂度和“实际秒数”混为一谈。

## 2. 直觉 / Intuition

假设只有 5 个数，逐个看一遍几乎没有任何压力。

但如果有 1000000 个数呢？

如果算法只需要每个数看一次，工作量大约跟数据规模一起增长。

如果每个数都要再和其他所有数比较一次，工作量可能按平方增长。

所以我们真正想观察的不是一次运行快不快，而是：

> **`n` 变大以后，执行次数增长得有多快？**

可以先建立这些直觉：

- `O(1)`：无论 `n` 多大，只做固定数量的工作；
- `O(log n)`：每一步都把问题按比例缩小，`n` 很大时步骤仍增长很慢；
- `O(n)`：数据有多少，工作量大致跟着增加多少；
- `O(n log n)`：比线性增长快，但远慢于平方增长；
- `O(n^2)`：`n` 变成 10 倍，主要工作量可能接近 100 倍。

---

## 3. 核心思想 / Core Idea

分析时间复杂度时，优先寻找：

> **随着 `n` 增长，哪部分工作的执行次数也在增长？**

当前程序有两个与 `n` 有关的主要循环：

1. 读入 `n` 个整数；
2. 从数组中继续扫描，寻找最大值。

每个循环都最多执行与 `n` 同数量级的次数。

因此总工作量大致是 `n + n`，常数倍不会改变增长级别，所以整体仍然写成 `O(n)`。

## 4. 手推 / Hand Simulation

以 `nums = [4, 1, 7, 3, 5]` 为例。

程序先令 `max = 4`，然后依次比较：

```text
1 > 4 ?  no
7 > 4 ?  yes → max = 7
3 > 7 ?  no
5 > 7 ?  no
```

对于 5 个元素，我们只需要从头到尾扫描一次。

## 5. 实现 / Implementation

本课保留真实学习代码：[`main.cpp`](./main.cpp)。

核心部分：

```cpp
max = elements[0];
for (std::size_t i = 1; i < elements.size(); i++)
{
    if (elements[i] > max)
    {
        max = elements[i];
    }
}
```

---

## 6. 复杂度 / Complexity

| 部分 | 时间复杂度 | 原因 |
| --- | --- | --- |
| 读入 `n` 个数 | `O(n)` | 每个输入处理一次 |
| 扫描寻找最大值 | `O(n)` | 每个元素最多比较一次 |
| 整体 | `O(n)` | `O(n) + O(n)` 仍是 `O(n)` |

---

## 7. 常见错误 / Common Mistakes

- 把复杂度理解成精确运行时间；
- 只看代码行数；
- 忽略最坏情况下需要遍历完整数据。
